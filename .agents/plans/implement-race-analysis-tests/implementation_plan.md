# Описание задачи

Создать "Test Data Builder" (паттерн Фабрика) для сущностей базы данных, чтобы упростить и стандартизировать создание мок-данных в тестах. После этого необходимо отрефакторить существующие тесты во всем проекте, чтобы они использовали этот новый билдер вместо создания захардкоженных объектов внутри самих тестов.

Это улучшит поддержку тестов, уменьшит дублирование кода и гарантирует, что мок-объекты строго соответствуют схемам Drizzle.

## Предлагаемые изменения

### `src/test/factories.ts`
Создать новый файл `src/test/factories.ts`, который будет содержать фабричные функции для создания валидных объектов схемы Drizzle. Каждая функция будет предоставлять значения по умолчанию, но при этом позволит переопределять любые поля с помощью аргумента типа `Partial<T>`.

Функции-фабрики (на основе `src/lib/db/schema.ts`), которые нужно реализовать:
- `buildRaceAnalysis`
- `buildGproCredentials`
- `buildDriverProfile`
- `buildCarPart`
- `buildRaceFuelAnalytics`
- `buildRaceCarSnapshot`
- `buildRaceDriverSnapshot`

### `src/lib/services/race-analysis.service.test.ts`
Отрефакторить тесты, заменив прямое создание мок-объектов вызовами фабрики `buildRaceAnalysis`.

### `src/app/fuel/actions.test.ts`
Отрефакторить тесты, заменив мок-объекты, возвращаемые базой данных (например, из метода `findFirst`), на вызовы соответствующих фабрик.

## План проверки (Verification Plan)
- Запустить `npm run typecheck`
- Запустить `npm run test`
